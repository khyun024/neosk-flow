## 1. 현재 방식: 참여 코드 입력 (난수번호 방식)

관객이 입장 시 받은 6자리 코드를 키오스크에 입력하고 시작한다. 코드 1개당 1회만 쓸 수 있어 재참여가 막힌다.

플로우: 대기화면 터치 → 코드 6자리 입력 → 이름 입력 → 설문 10문항 → 공명 분석 → **결과 공개(인쇄 자동 시작) → 보이스** → 완료

예시 모드(현재 프로토타입, 서버 없음)의 동작:

- 형식(6자리)만 맞으면 유효한 코드로 처리한다
- 한 번 쓴 코드는 키오스크 기기 안(localStorage)에 기록되어 다시 입력하면 "이미 사용된 코드입니다"가 뜬다
- 스태프 기능: 대기화면 STEP 0 라벨 5회 연속 터치는 코드 없이 시작(테스트용), 코드 화면 STEP 1 라벨 5회 연속 터치는 사용 기록 초기화(그 뒤 같은 코드로 재입장 가능)

실제 개발로 갈 때 달라지는 것:

- 발급된 코드 5만 개 목록과 대조한다. 키오스크가 1대면 목록을 기기에 내장하고 사용 기록도 기기에 남기면 서버가 필요 없다. 여러 대면 사용 처리를 서버(구글 시트 등)에서 공유해야 한 코드가 두 대에서 겹쳐 쓰이지 않는다
- 코드 발급 방법은 운영 선택: 입장권에 인쇄, 리플렛 스티커, 현장 배부 카드 등

## 1-1. 이름 입력 규칙 (2026-08-06 변경)

‘이름 없이 시작’ 버튼을 없애고 이름을 필수로 바꿨다. 입력한 이름은 멤버 보이스가 호명하는 데 쓰이므로, 그대로 읽었을 때 문제가 되는 입력을 두 단계로 막는다. 버튼을 누를 때 검사하고, 통과하지 못하면 사유가 입력창 아래에 뜬다.

1. **완성된 글자만 허용** — 초성·모음이 하나라도 남아 있으면 거부한다(ㅋㅋㅋ, ㅎㅇ, ㅏㅏ, 박ㅅ). 한글과 영문 모두 쓸 수 있고, 영문 이름은 호격 조사(아/야) 없이 그대로 호명된다.
2. **금칙어 차단** — 욕설·비속어·성적 표현·혐오 표현. 우회 입력에 대응해 두 가지로 검사한다.
   - 정규화 대조: 소문자화, 공백·기호 제거, 반복 문자 축약 → "시 발", "시발발발" 차단
   - 자모 분해 대조: 묵음 ㅇ 제거 후 반복 축약 → "시이발", "씨이발"처럼 글자를 끼워 넣는 우회 차단

금칙어 목록은 스크립트 상단 `BANNED` 배열 한 곳에 모아 두었다. 운영 중 새로운 시도가 발견되면 이 배열에 단어만 추가하면 된다. 실존 인명과 겹쳐 오탐이 나는 단어는 반대로 지우면 된다.

검증: 실제 이름 15종(지민·수빈·시온·보영·상아·Mark 등)은 전부 통과, 우회 입력 20종(초성만·띄어쓰기·끼워넣기·영문 욕설 등)은 전부 차단되는 것을 확인했다.

한계: 문자 필터는 원리상 완전할 수 없다. 새로운 우회 표기는 계속 나오므로 현장에서 목록을 보강하는 운영이 전제다. 출력물(포토카드)에 이름이 인쇄된다면 스태프가 최종 확인하는 절차를 두는 편이 안전하다.

## 1-2. 결과 화면 변경 (2026-08-06, 검토 의견 반영)

**순서를 바꿨다.** 기존에는 목소리를 먼저 들려주고 결과 카드를 보여줬으나, 결과를 먼저 공개하고 그다음에 목소리를 들려주는 순서로 변경했다. 매칭 결과가 먼저 드러나야 이어지는 목소리가 그 멤버의 것으로 받아들여진다.

**STEP 5 결과 공개** — 화면 구성을 시안대로 단순화했다.

- 상단: "당신의 신호가 닿은 멤버" + 멤버 이름
- 중앙: 멤버 사진 구역 (다른 요소 오버레이 없음)
- 하단: "헤드폰을 착용하세요" 안내 → 목소리 듣기 버튼

삭제한 요소: 신호 일치 개수(5/10), 근접 신호(2·3위), 화면 QR코드. 매칭 근거를 숫자로 보여주면 결과가 계산으로 읽히고, QR은 인쇄된 포토카드에만 있으면 충분하다.

**STEP 6 보이스** — 멤버 대사(호명 → 자기소개 → 고유 메시지)가 재생된다. 재생이 끝나면 자동으로 완료 화면으로 넘어간다.

### 버튼 정리 (2026-08-07, 최수영님 의견 반영)

- **‘인쇄하기’ 버튼 삭제** — 결과가 공개되는 순간 출력이 이미 자동으로 시작되므로 누를 버튼이 필요 없다. 대신 화면을 가리지 않는 하단 상태 표시로 "포토카드 출력 중… → 출력 완료 · 출력구를 확인하세요"를 보여준다. 기존의 전체 화면 인쇄 오버레이는 없앴다.
- **‘처음으로’ 버튼 삭제** — 목소리 재생이 끝나면 완료 화면을 거쳐 자동으로 대기화면에 복귀한다(재생 후 완료, 4.2초 뒤 초기화). 중간 이탈은 기존 70초 무입력 복귀가 처리한다.
- **‘목소리 듣기’ 버튼은 유지** — 헤드폰 착용 안내가 뜬 뒤 관객이 직접 눌러야 재생된다. 자동 재생하면 헤드폰을 쓰기 전에 도입부를 놓치기 때문이다.

결과적으로 관객이 누르는 버튼은 코드 입력·이름 입력·설문 선택·목소리 듣기뿐이고, 결과 공개 이후에는 목소리 듣기 하나만 남는다.

**확인 필요(미결)**: 화면에 띄우는 멤버 사진을 실제 인쇄될 포토카드 사진과 같은 컷으로 할지, 화면용과 인쇄용을 다르게 갈지. 인쇄 포토카드 요소(멤버 초상, 국문·영문 이름, 친필 손글씨, 친필 사인, 카드 코드, QR)는 화면 구성과 별개로 유지된다.

## 2. 코드 자릿수 계산 (5만 개 기준)

5만 개를 담는 것 자체는 4자리면 되지만, 중요한 것은 아무렇게나 찍은 입력이 통과할 확률을 낮추는 것이다.

| 방식 | 전체 조합 | 무작위 입력이 유효할 확률 | 판정 |
|---|---|---|---|
| 숫자만 5자리 | 10만 | 1/2 | 불가 |
| 숫자만 8자리 | 1억 | 1/2,000 | 가능 |
| 영숫자 31종 5자리 | 2,862만 | 1/573 | 아슬아슬 |
| 영숫자 31종 6자리 (권장) | 8.9억 | 1/17,800 | 충분 |
| 기존 엑셀 12자리 | 2.5경 | 사실상 0 | 과잉, 타이핑 부담 |

권장: 혼동 문자(0·1·I·L·O)를 뺀 영숫자 31종 × 6자리. 키오스크 키패드도 이 31자만 노출해 오입력을 줄인다. 기존 12자리 코드(SMTOWN 리워드용)와는 용도가 다르므로 별도 세트로 발급하면 된다.

## 4. 참고: QR 방식 (이전 검토안)

휴대폰으로 키오스크 QR을 찍으면 서버가 참여 이력을 확인해 키오스크를 자동 시작시키는 방식도 구현해 두었다(gate.html, server.gs). 코드 배부 없이 운영할 수 있는 대신, 차단 단위가 휴대폰 브라우저라서 시크릿 모드로 우회가 가능하고 서버와 인터넷이 필요하다. 코드 방식으로 확정되면 이 두 파일은 지워도 된다.

## 5. 난수코드와 포토카드 QR 5만 개 문제

전제: 난수코드 5만 개는 이미 확보됨 (NEOSK_난수코드_멤버배분_21종.xlsx, G 시작 12자리, 21명 멤버 블록 배분, SMTOWN 앱 등록용 매핑 포함).

- 포토카드에 넣을 QR 이미지 5만 개를 미리 만들 필요는 없다. 키오스크가 인쇄 직전에 해당 멤버 블록의 다음 미사용 코드를 꺼내 즉석에서 QR로 그리면 된다. 필요한 것은 코드 5만 개(확보 완료), 인쇄 시점 QR 생성, 멤버별 사용 순번 카운터다
- QR에는 코드만 넣지 말고 `https://도메인/r/GDFECNG2FT2N` 형태의 URL로 넣는 것을 권한다. 찍는 순간 풀 인터뷰 페이지가 열리고 서버가 그 코드를 사용 처리하면 카드 QR 자체가 1회용이 된다
- 카드를 인쇄소에서 미리 찍는 방식이라면 그때는 장마다 다른 QR 5만 장이 맞고, 가변데이터 인쇄(VDP)에 전체매핑 시트에서 뽑은 CSV를 넘기면 된다
- 키오스크가 2대 이상이면 같은 멤버 블록의 코드가 겹치지 않도록 기기별 순번 구간을 나누거나 서버에서 발급한다
